# 2026-09-23 — Bake House

## What was built

Full production build of **Bake House**, a functional clone of `freshbakes.store`
driven by `docs/freshbakes-clone/CLONE-SPEC.md` + 35 reference screenshots.

Stack: Vite 6 + React 18 + TypeScript + Tailwind v4, `react-router-dom` for the
two routes (`/` shop, `/dashboard/*` back office). No backend — all state lives in
one React context (`src/lib/store.tsx`) persisted to `localStorage` under
`bakehouse.v1`.

### Key files
- `src/lib/types.ts` — BoxSize, BOX_PRICES (4/6/12 = $22/$30/$54), DELIVERY_FEE $6,
  the 9 covered postcodes, Flavour/Box/Order models.
- `src/lib/data.ts` — brand, 9 flavours, reviews, FAQ, explainer, dashboard seed.
  All copy is original (the spec forbids copying brand/copy/photos 1:1).
- `src/lib/store.tsx` — the whole state machine: boxes, stock, pricing, fulfilment,
  customer, payment, missed demand, toasts, checkout step.
- `src/components/Cookie.tsx` — cookies are **drawn, not photographed**: a seeded
  PRNG generates a wobbly outline + chunks + crumbs per flavour. Deterministic, so
  a flavour always renders the same bake. `photo` on a Flavour overrides it.

## Decisions worth remembering

1. **Rebranded, per the spec.** The brief says clone the *functionality*, not the
   brand — change name, colours, photos, copy. The repo is named `bake-house`, so
   that became the brand. Every section, state and interaction matches the
   screenshots; only the words and palette are ours.
2. **Stock math:** `available = stock - qtyAcrossAllBoxes`. Cards show the
   decremented count immediately (optimistic), and `stock` is only reduced
   permanently on Place Order. This reproduces both observed states — "11 LEFT
   TODAY" ticking down and "ALL IN YOUR ORDER" when the last one is in the box.
3. **Size change resets the box** (spec §15 open question) — matches the observed
   6→4 behaviour. Silent, no toast.
4. **Mobile sticky bar only appears when the cart is non-empty.** The spec text
   says "always visible" but screenshot 30 shows no bar on an empty cart.
5. **Mobile hero copy sits above the carousel card.** The original appears to omit
   the H1 on mobile (same class of gap as the missing mobile nav, which the spec
   explicitly says to fix rather than replicate).
6. **Dashboard Menu tab writes to the same store as the shop**, so "Save and
   update the shop" genuinely changes the storefront. Photo URL is a real
   override, not a dead field.
7. **Windows carry an explicit `start` label** (`WINDOW_STARTS` in Checkout.tsx) so
   the confirmation can say "See you from 11.00am." instead of deriving am/pm.

## Second pass — audit (`/tmp/audit-bakehouse.mjs`, 29 checks)

The first suite proved the happy paths. This one went after the states nobody had
exercised, and found four real bugs the happy path never touched:

1. **Escape did nothing when focus was outside the dialog.** The handler was a
   React `onKeyDown` on the overlay, so it only fired while focus was inside. A
   click on a non-focusable part of the panel drops focus to `<body>` and Escape
   dies. Moved both Escape and the Tab trap to a `document` listener in
   `useDialog`; the hook now returns `{ ref }` only.
2. **The batch grid imported `FLAVOURS` from `lib/data.ts` instead of reading
   `useShop().flavours`.** The carousel read the store, so it updated — the grid
   did not, which made the dashboard's "Save and update the shop" a lie for the
   one place customers actually look. Always read flavours from the store.
3. **Contrast failure.** `--color-ink-faint` (#a3947f) on cream was 2.96:1, and it
   carries the review meta line, card index numbers and the dashboard sub-labels.
   Re-toned: ink-soft → #635647 (6.33:1), ink-faint → #75685a (4.81:1). Both now
   clear AA on the cream shell.
4. **Touch targets.** The spec calls for ≥44px on mobile Add/stepper/COPY. They
   were 32–36px. Bumped mobile-first (`h-11 w-11 sm:h-8 sm:w-8` and
   `min-h-11 sm:min-h-0`) across the grid, carousel controls, size pills, COPY
   rows, day/window/payment pickers, dialog close buttons and the dashboard rows.

Also hardened the menu stock input against `NaN` (a non-numeric keystroke used to
persist `NaN` into state).

### Harness lessons (cost me two false failures)

- `offsetParent !== null` is **not** a visibility test for `position: fixed`
  elements, and a card's Add control flips from `Add X to your box` to
  `Add another X` after the first add — a test that only knows the first label
  silently no-ops.
- The mode cards (Pickup/Delivery) only exist on checkout **step 1**; asserting
  them while the dialog sits on step 3 reports a missing control that is not
  missing.
- `main input` on the Menu tab matches the **stock number field** first, not the
  name field.

Final state: **48/48 main (dev) · 48/48 main (production dist) · 29/29 audit**,
zero console errors.

## Third pass — edge cases + dead code (`/tmp/edge-bakehouse.mjs`, 27 checks)

Two more real defects, both of which the happy-path suites could not have caught.

1. **The desktop checkout CTA was unreachable with a mouse.** The sticky box panel
   was 984px tall against a 900px viewport; because the panel is `sticky`, its
   bottom 443px — including the CTA and "+ add another box" — sat permanently
   below the fold and scrolling never revealed it. Every automated test had been
   clicking it programmatically, which works regardless of geometry.
   Fixed by capping the panel at `lg:max-h-[calc(100dvh-112px)]` with
   `grid-rows-[minmax(0,1fr)_auto]`: the body scrolls, the total + CTA are pinned
   to the panel's bottom. Note the flex equivalent (`flex-col` + `flex-1` on the
   body) collapses the panel to padding + footer, because the container's height
   is content-driven — the grid track is what makes it definite.

2. **A box of six could take ten cookies.** `stateRef.current = state` is only
   refreshed on render, and React batches `setState`. Ten clicks dispatched in one
   task all read the pre-batch ref, so the capacity guard passed every time:
   `BOX 1 · 10/6`. Same root cause made the "n of 6" toast repeat. Fixed with a
   `commit()` helper that writes the ref synchronously; `add`, `remove`, `setSize`,
   `addBox`, `removeBox`, `ensureRef` and `placeOrder` all go through it, and
   `placeOrder` now derives the basket and total from committed state rather than
   render-time memos.

Also removed dead code (`money2`, `DAYS_AHEAD`, the unused `CUSTOMERS[].initials`
field) and wired the previously-unused `hardReset` into a **"Reset this demo"**
control in the footer — without it, one order depletes stock permanently with no
way back, which is a bad demo.

### Harness lessons (three more false failures)

- `.rounded-\[26px\]` inside a **template literal** loses its backslash before the
  page parses the selector → `SyntaxError: not a valid selector`. In a plain
  single-quoted string it survives (it goes through `JSON.stringify`). Prefer
  structural selectors (`ul.grid`, `el.closest('div')`) over escaped class names.
- `#build h3` matched the box panel's "Box 1" heading, not the card heading —
  use `#build article h3`.
- After navigating to `/dashboard/` for a sidebar check, the shop-only elements
  (`.ticker-track`, the box builder) do not exist. Navigate back before asserting
  them. Three separate checks failed on this before it was obvious.
- `offsetParent`-style visibility filters and `sticky` preconditions are fragile.
  Assert **scroll-independent invariants** instead: "panel height ≤ viewport − 92",
  "CTA sits in the panel's bottom band", "CTA bottom ≤ viewport height".

Final state: **48/48 · 48/48 · 29/29 · 27/27 = 152 checks**, zero console errors.

## Fourth pass — real photography + document structure (`/tmp/polish-bakehouse.mjs`, 16 checks)

The user supplied 11 generated cookie photos in `src/imgs/` (1254×1254, ~2.1MB each).

### Mapping and processing

Nine were needed. Two were spares: a second raspberry dark, and a plain choc-chip
with no sea salt that didn't match Salted butter chip's description. The full
source→flavour table is in `picture.md`.

Background removal is done by **flood-filling inwards from the frame edge**, not by
keying out white. Three of these cookies (triple chocolate, matcha, red velvet)
have white chocolate chips — a naive white→transparent key would hollow them out.
Then: trim to the cookie bbox, re-centre square with a 7% margin, resize to 720²
(the largest real use is the carousel at 280 CSS px, so that covers 3× on mobile),
export WebP q84. **2.1MB → ~115KB each, 1.0MB for all nine.** `dist/` is 1.4MB.

Wired via the `photo` field on every flavour in `src/lib/data.ts` — the mechanism
already existed, so no component changes were needed beyond making the photo path
share the drawn-cookie path's inset (otherwise photos render larger than SVGs) and
dropping a redundant `rounded-full` that risked clipping.

`src/imgs/` is **29MB of source that never ships** — Vite ignores unreferenced
files, and nothing leaked into `dist/`. Worth knowing it is in git.

### Document-structure findings

- **The carousel's flavour name was an `h2` placed before the page `h1`** in DOM
  order, so a screen reader announced a slide label before the page title. It is a
  slide label, not a section heading — now a `<p>`.
- Print now hides the shop's announcement bar, ticker and header (previously only
  the mobile order bar had `no-print`).
- The bake sheet printed "1 **trays**" and printed its own PRINT button. Both fixed.

### One honest non-fix

Exporting the whole 6100px shop page to PDF **hangs headless Chrome** (>90s, with
or without backgrounds). Measured: bake sheet 72ms, shop page 1 260ms, full page
>90s. That is a headless limitation on very tall pages, not a defect — the bake
sheet, which is the only page the spec asks to print, renders in 72ms. The polish
check now exports page 1 instead of pretending the full-page case works.

Final state: **48/48 · 48/48 · 29/29 · 27/27 · 16/16 = 168 checks**, zero console errors.

## Fifth pass — loading behaviour (`/tmp/loading-bakehouse.mjs`, 12 checks)

Nothing had measured how the page actually loads, which matters more now that it
carries nine photos. Runs against the production `dist/`.

Measured on the shop page:

| | |
|---|---|
| Total transfer | **1135 KB** — 1045 cookies, 82 JS, 9 CSS, 1 font |
| Requests | 12 |
| Cumulative layout shift | **0.0026** (good is < 0.1) |
| Failed requests | none, on the shop or the dashboard |
| Cookie images | 9 unique, all `image/webp`, all decoding at 720² |

Also asserted the lazy-loading split: 18 of 19 cookie `<img>` tags are
`loading="lazy"`, and the carousel image — the one above the fold — deliberately
is not. The nine files are requested once each and shared by all 19 `<img>` tags
via the browser cache.

### Robustness fix

A renamed or deleted photo file previously left a **broken-image icon** in the
product grid. `CookieTile` and the carousel image now catch `onError` and fall
back to the drawn SVG cookie. Keyed on the URL, so editing the Photo URL in the
dashboard retries rather than staying stuck on the failed source. Covered by a
check that points a flavour at a nonexistent file and asserts the SVG appears.

### Harness bug

`[].slice.call(new Set(...))` returns `[]` — `slice` needs an array-like with
`length`, and a `Set` has none. Use `Array.from` or `[...set]`. Cost one false
"cookie images are not all the same size" failure on images that were all 720².

Final state: **48 · 48 · 29 · 27 · 17 · 12 = 181 checks**, zero console errors.
